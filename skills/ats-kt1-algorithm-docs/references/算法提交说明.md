

# 算法提交说明

## 1. 说明概述

为统一执行、测试和展示各类算法模型，现采用 **Docker 镜像打包** 的方式提交算法。
提交时，需要对算法软件、输入输出目录结构、镜像命名方式、运行参数配置和测试用例组织形式进行统一约定，以确保测试环境能够直接加载并运行算法。

测试时，算法输入放置在 `input/` 文件夹中，算法输出需写入 `output/` 文件夹中。
容器运行时会自动挂载这两个目录，因此请严格按照约定路径读取输入、保存输出。

默认测试命令如下：

```bash
docker run --rm \
  --volume ./input:/app/data/input \
  --volume ./output:/app/data/output \
  algo1-4-j-100:v1
```

除上述默认目录映射外，如需额外参数，例如 GPU、共享内存等，请写入 `params.json` 文件中（详见7.4）。

---

## 2. 提交目标

算法提交需满足以下目标：

1. 能够在统一的 Docker 环境下直接运行；
2. 能够按照固定目录读取输入并生成输出；
3. 能够通过统一命名规则完成归档、管理和测试；
4. 能够提供基础测试用例和可替换测试用例，便于验证算法的适应性与鲁棒性。
5. **（重要）**一定要确保模型运行之后，**output文件夹里有输出的文件**，例如json/csv/txt/png等。

---

## 3. Docker 镜像构建要求

### 3.1 基本环境准备

#### 1）安装 Docker

请先在本地环境中安装 Docker。
建议优先使用 **Ubuntu** 进行镜像构建和运行，因为 Windows 下构建和执行效率通常较低。

#### 2）配置国内镜像源（可选）

可在 Ubuntu 中编辑 Docker 配置文件：

```bash
vim /etc/docker/daemon.json
```

添加如下内容：

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://registry.docker-cn.com",
    "https://mirror.baidubce.com"
  ]
}
```

然后重启 Docker 服务并验证：

```bash
service docker restart
sudo systemctl status docker
```

## 4. 镜像构建说明

### 4.1 构建思路

通常建议基于一个合适的官方基础镜像进行构建，例如 PyTorch 官方镜像。
然后将算法代码复制到镜像中，安装依赖，配置环境，并设置默认启动命令。

典型 Dockerfile 结构如下：

```dockerfile
FROM pytorch/pytorch:2.3.0-cuda11.8-cudnn8-devel

WORKDIR /app

COPY ./algo4-1-J-11 /app

CMD ["python", "opencood/tools/inference.py", "--model_dir", "opencood/test_examples/4-1-J-11"]
```

其中：

- `/app` 为容器内默认工作目录；
- 算法代码默认放置在 `/app` 下；
- `CMD` 用于指定容器启动后的默认执行命令。

---

### 4.2 推荐的两步构建方式（供参考）

对于依赖较多、环境复杂的算法，建议采用“**基础环境镜像 + 具体算法镜像**”的两步构建方式。

这种方式的优点是：

- 同一框架下多个算法可复用基础环境；
- 避免重复安装相同依赖；
- 提高后续镜像构建效率。

---

### 4.3 基础环境镜像示例

#### Dockerfile 示例

```dockerfile
FROM pytorch/pytorch:2.3.0-cuda11.8-cudnn8-devel

ENV DEBIAN_FRONTEND=noninteractive

ENV CUDA_HOME=/usr/local/cuda \
    PATH=/usr/local/cuda/bin:${PATH} \
    LD_LIBRARY_PATH=/usr/local/cuda/lib64:${LD_LIBRARY_PATH} \
    TORCH_CUDA_ARCH_LIST="8.6;8.0;7.5;6.1"

RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential cmake git wget curl python3-pip libgl1-mesa-glx \
    && rm -rf /var/lib/apt/lists/*

RUN apt-get install -y libx11-6

WORKDIR /app

COPY ./algo4-1-J-11 /app

RUN pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/
RUN pip install --upgrade pip
RUN pip install --no-cache-dir -r requirements.txt
RUN pip install spconv-cu120
```

#### 构建命令

```bash
docker build -t algo-base-env:base -f Dockerfile .
```

#### 启动容器进行环境调试

```bash
docker run --gpus all -it \
  --name algo-base-env-dev \
  --shm-size=16g \
  --ipc=host \
  --volume ./input:/app/data/input \
  --volume ./output:/app/data/output \
  algo-base-env:base \
  /bin/bash
```

#### 进入容器后继续安装和调试

```bash
docker start algo-base-env-dev
docker attach algo-base-env-dev
```

容器内操作示例：

```bash
conda install xxx
pip install xxx
python setup.py develop
exit
```

#### 保存为新的基础镜像

```bash
docker commit algo-base-env-dev base-env:latest
```

---

### 4.4 具体算法镜像示例

在完成基础镜像后，可进一步构建具体算法镜像。

#### Dockerfile 示例

```dockerfile
FROM algo-base-env:latest

WORKDIR /app

COPY ./opencood/test_examples /app/opencood/test_examples

CMD ["python", "opencood/tools/inference.py", "--model_dir", "opencood/test_examples/4-1-J-11"]
```

#### 构建命令

```bash
docker build -t algo4-1-j-11:v1 -f Dockerfile .
```

#### 运行验证命令

```bash
docker run --rm \
  --volume ./input:/app/data/input \
  --volume ./output:/app/data/output \
  --gpus all \
  --shm-size=16g \
  algo4-1-j-11:v1
```

最终目标是，运行上面docker命令，可以自动执行算法程序，并在output文件夹中生成结果文件，执行完后自动退出docker。

#### 保存镜像

```bash
docker save algo4-1-j-11.tar algo4-1-j-11:v1
```

## 5. 提交包目录结构规范

所有算法提交内容需打包为一个 `.zip` 压缩包（zip内直接是各个子文件，不要再嵌套一层文件夹），目录结构如下：

```text
algo1-1-z-1.zip
├── algo1-1-z-1.tar
├── input/
├── output/
├── params.json
├── test_options/
├── algo1-1-z-1测试说明.docx
└── algo1-1-z-1模型原理说明.docx
```

---

## 6. 命名规则

所有文件和镜像名称应遵循统一命名规则：

### 6.1 命名格式

命名形式统一为：

```text
algo(课题编号)-(模型编号)
```

例如：

- `algo1-p-d-a3-1`
- `algo1-1-4-j-2`
- `algo4-1-z-1`

### 6.2 命名要求

1. 文件名中的英文字母统一使用 **小写**；
2. 提交压缩包名称应与算法名称保持一致；
3. Docker 镜像名称应与算法名称保持一致；
4. 镜像版本号统一使用 `v1`。

### 6.3 示例对应关系

- 压缩包名：`algo4-1-z-1.zip`
- 文件夹名：`algo4-1-z-1`
- 镜像名称：`algo4-1-z-1`
- 镜像文件名：`algo4-1-z-1.tar`
- 镜像版本：`v1`

### 6.4 打包要求

最终上传时应打包为一个 zip 文件，例如：

```text
algo1-1-z-1.zip
```

注意：**zip 内不要再额外嵌套一层同名文件夹**。

## 7. 提交文件用途说明

### 7.1 `algo1-1-z-1.tar`

Docker 镜像导出的 tar 文件，用于测试环境加载镜像。

### 7.2 `input/`

算法运行时的输入目录。
测试时，输入数据会放置在该目录下，并挂载到容器中的：

```text
/app/data/input
```

### 7.3 `output/`

算法运行时的输出目录。
算法必须将输出结果写入该目录，对应容器内路径为：

```text
/app/data/output
```

### 7.4 `params.json`

用于记录默认运行命令之外的额外 Docker 参数。
例如，若运行命令为：

```bash
docker run --rm \
  --volume ./input:/app/data/input \
  --volume ./output:/app/data/output \
  --gpus all \
  --shm-size=16g \
  algo4-1-j-11:v1
```

则 `params.json` 可写为：

```json
{
  "gpus": "all",
  "shm-size": "16g"
}
```

该文件的作用是：在统一执行命令的前提下，补充额外的运行参数，例如 GPU 需求、共享内存大小等。

注意事项：

1. `params.json` 内容必须为合法 JSON；
2. 不要在 `params.json` 中添加额外的目录映射；
3. 固定目录映射仅允许使用：
   - `/app/data/input`
   - `/app/data/output`

### 7.5 `test_options/`

用于存放额外测试用例。
测试人员可从该目录中选择其他测试样例替换 `input/` 中的默认输入，以验证算法在不同场景下的表现。

### 7.6 `algo1-1-z-1测试说明.docx`

用于说明算法模型的测试流程、运行方式、输入输出说明及其他必要信息。模板见附录。

### 7.7`algo1-1-z-1模型原理说明.docx`

用于介绍说明算法模型基本信息、算法模型简介、算法流程及其他必要信息。模板见附录。

## 8. 默认测试命令约定

测试时默认执行以下 Docker 命令：

```bash
docker run --rm \
  --volume ./input:/app/data/input \
  --volume ./output:/app/data/output \
  algo1-1-z-1:v1
```

### 8.1 约定说明

1. 默认命令仅包含输入输出目录映射；
2. 其余运行参数需写入 `params.json`；
3. 不允许修改默认输入输出挂载路径；
4. 容器内默认工作目录为：

```text
/app
```

建议在 Dockerfile 中显式设置：

```dockerfile
WORKDIR /app
```

## 9. 镜像版本约定

最终提交的 Docker 镜像版本号统一设置为：

```text
v1
```

例如：

```text
algo1-1-z-1:v1
```

## 10. 可变测试用例要求

为验证算法的适应性与鲁棒性，除默认测试输入外，还需额外提供 **2 至 3 组** 可替换测试用例。

### 10.1 默认测试用例

在 `input/` 文件夹中放置一组基础输入用例，要求算法在执行 Docker 命令后能够自动读取输入并生成输出。

### 10.2 额外测试用例

在 `test_options/` 文件夹中放置 2 至 3 组额外测试用例。
测试人员可根据需要，从中选取测试数据替换 `input/` 目录内容后再次运行容器。

### 10.3 要求

1. 每组测试用例应具备完整输入内容；
2. 替换后无需修改代码或镜像配置即可直接运行；
3. 算法应保持一致的输入读取方式和输出保存方式。

## 11. 提交前检查清单

提交前请确认以下事项：

### 11.1 镜像与目录

- [ ] Docker 镜像已成功构建；
- [ ] 镜像已导出为 `.tar` 文件；
- [ ] 输入目录为 `/app/data/input`；
- [ ] 输出目录为 `/app/data/output`；
- [ ] 工作目录已设置为 `/app`。

### 11.2 命名规范

- [ ] 压缩包名称符合规范；
- [ ] 镜像名称符合规范；
- [ ] 文件名全部使用小写英文；
- [ ] 镜像版本统一为 `v1`。

### 11.3 提交文件完整性

- [ ] 包含镜像 tar 文件；
- [ ] 包含 `input/`；
- [ ] 包含 `output/`；
- [ ] 包含 `params.json`（如有额外运行参数）；
- [ ] 包含测试说明文档；
- [ ] 包含 `test_options/`。

### 11.4 运行验证

- [ ] 使用默认命令（加上额外参数）可正常运行；
- [ ] 使用额外测试用例可正常运行；
- [ ] 输出结果正确写入 `output/` 目录；
- [ ] 不依赖额外人工修改路径或命令。

---

## 12. 总结

算法提交的核心要求是：
**镜像可直接运行、目录结构统一、命名规则统一、输入输出路径固定、额外参数规范配置、测试用例完整可替换。**

请各算法提交方在打包前完成本说明中的逐项检查，以确保后续测试、验收和展示过程顺利进行。
