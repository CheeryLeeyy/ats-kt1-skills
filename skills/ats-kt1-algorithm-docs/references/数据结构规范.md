## 测试说明 JSON

每个算法使用 `algo1-4-j-N.json`。必填项：

- `algorithm_id`：`1-4-J-N`。
- `package_name`：`algo1-4-j-N`。
- `algorithm_name`：最新命名表中的当前名称。
- `image`：`algo1-4-j-N:v1`。
- `input_files`：默认 `input/` 中的真实输入文件。
- `test_options`：`test_options/` 中可完整替换 `input/` 的真实样例；可为空。
- `test_options_limitation`：`test_options` 为空时必填，如实说明未提供样例。
- `runtime_configs`：每次 Docker 运行所需配置，不得混入 `test_options`。
- `load_command`、`linux_command`、`windows_command`、`run_note`：镜像加载与容器运行信息。
- `output_files`：正常运行后预期产物。
- `input_files[].fields`、`output_files[].fields`：模型原理说明表使用的文件内部字段；每项包含 `name`、`type`、`description` 和 `content`。测试说明生成器可忽略该扩展字段。
- `results`：第 3 章预期结果内容。
- `conclusion`：第 4 章测试通过条件，必须包含当前算法名称、业务编号、“预期”、“可以判断”和“测试通过”。

示意结构：

```json
{
  "algorithm_id": "1-4-J-1",
  "package_name": "algo1-4-j-1",
  "algorithm_name": "当前模型名称",
  "image": "algo1-4-j-1:v1",
  "input_files": [
    {
      "name": "input/config.json",
      "title": "配置输入",
      "format": "json",
      "required": "是",
      "description": "包含算法必需的输入字段。",
      "detail": "解释实际字段、取值和尺寸。",
      "fields": [
        {"name": "field", "type": "str", "description": "业务字段", "content": "本次输入中的具体取值或内容"}
      ],
      "content": {"type": "table", "headers": ["字段", "说明"], "rows": [["field", "含义"]]}
    }
  ],
  "test_options": [],
  "test_options_limitation": "提交包未提供额外可替换输入样例。",
  "runtime_configs": [
    {"name": "gpus", "type": "str", "default": "all", "range": "all或设备编号", "description": "提供GPU访问。"}
  ],
  "runtime_config_intro": "说明当前算法的容器运行方式。",
  "runtime_config_source": "params.json与镜像默认入口",
  "load_command": "docker load -i algo1-4-j-1.tar",
  "linux_command": "docker run --rm --volume ./input:/app/data/input:ro --volume ./output:/app/data/output algo1-4-j-1:v1",
  "windows_command": "docker run --rm --volume \"${PWD}/input:/app/data/input:ro\" --volume \"${PWD}/output:/app/data/output\" algo1-4-j-1:v1",
  "run_note": "在算法包根目录执行。",
  "execution_summary": "仅概括容器运行的实测情况。",
  "output_files": [
    {
      "name": "result.json",
      "format": "json",
      "description": "运行后预期生成，包含status和业务指标。",
      "fields": [
        {"name": "status", "type": "str", "description": "运行状态", "content": "正常完成时为ok"}
      ]
    }
  ],
  "results": [
    {
      "title": "output文件夹预期生成内容",
      "description": "正常运行后预期生成下列文件。",
      "content": {"type": "table", "headers": ["文件", "字段"], "rows": [["result.json", "status、metric"]]}
    }
  ],
  "conclusion": [
    "当前模型名称（1-4-J-1）运行后预期生成result.json。",
    "当文件可解析且内容满足业务需求时，可以判断该算法模型测试通过。"
  ]
}
```

## 内容块

`input_files[].content` 和 `results[].content` 支持：

- `{"type": "text", "text": "..."}`
- `{"type": "code", "text": "..."}`
- `{"type": "table", "headers": ["..."], "rows": [["..."]]}`

大型文本只放代表性节选。二进制、权重、NPZ、NPY、Parquet、点云和图像使用 shape、dtype、尺寸、字段、统计或哈希摘要说明。

## 模型原理 spec JSON

每个算法编写 `/work/model-specs/algo1-4-j-N.json`，只包含需要人工根据旧文档和当前算法归纳的原理内容：

```json
{
  "function_description": "模型功能描述",
  "service_scene": "模型服务场景",
  "responsible_unit": "责任单位",
  "intro_paragraphs": ["详细问题背景。", "详细模块组成。", "详细处理链路。", "详细关键配置与输出。"],
  "framework_nodes": [
    "输入解析：读取并校验测试说明中的真实输入",
    "数据预处理：完成格式转换和质量检查",
    "核心计算：执行当前算法的主要计算过程",
    "协同处理：完成节点间传输、融合或聚合",
    "结果整理：形成业务指标和结构化结果",
    "结果输出：写入测试说明中的真实输出文件"
  ],
  "flow_steps": [
    "步骤1：读取真实输入文件并解析字段",
    "步骤2：完成数据清洗、对齐或特征准备",
    "步骤3：由核心模块执行主要算法计算",
    "步骤4：完成节点协同、传输、聚合或融合",
    "步骤5：计算业务指标并整理结果结构",
    "步骤6：将结果写入真实输出文件"
  ]
}
```

`intro_paragraphs` 至少 4 段且合计不少于 350 个中文字符。`framework_nodes` 必须恰好 6 项，每项使用“中文模块名：作用说明”，侧重子模块职责和关系，不能只写模块名。`flow_steps` 必须恰好 6 项，侧重从输入到输出的数据操作，每项具体说明数据、模块作用和处理方式，不能直接复制、换序或纵向排列框架节点。原理 spec 还必须填写 `input_summary` 和 `output_summary`，各用一至两句中文概括业务数据，不得罗列文件名、路径、变量名或数量。可选填写 `project_name` 和 `topic_name`。“支持的协同场景”不在 spec 中手填，由 `extract_latest_names.py` 从模型清单 C–F 列提取并由 `prepare_model_principle_data.py` 合并为 `supported_scenarios` 和 `supported_scenarios_text`。

## 模型原理生成 JSON

不手工重复编写。使用 `prepare_model_principle_data.py` 将最新命名、已校验测试 JSON 和原理 spec 合并。生成数据中的 `inputs` 和 `outputs` 必须与测试 JSON 的算法数据文件一致，但必须排除算法根目录中标为 `runtime_only` 或 `role: docker-runtime` 的 Docker 运行配置；算法在 `input/` 内实际读取的同名业务数据仍应保留。

每个 `inputs[]` 和 `outputs[]` 使用以下结构：

```json
{
  "name": "result.json",
  "file_description": "结构化算法运行结果",
  "format": "json",
  "fields": [
    {
      "name": "status",
      "type": "str",
      "description": "运行状态",
      "content": "正常完成时为ok"
    }
  ]
}
```

中列显示 `file_description` 和 `name`，同一文件有多个字段时纵向合并中列；右列逐行显示 `fields[]`，不得合并。优先使用测试 JSON 中显式提供的 `fields`；旧数据未提供时，准备脚本可从测试说明的表格或代码节选提取，但生成前必须人工核对变量名、类型和具体内容。
